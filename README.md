# minecraft-civ-duels

Плагин дуэлей для Paper 26.3 (Java 25): рейтинговые матчи 1 на 1, тренировочные комнаты, бой с ботом-мишенью, наборы брони и оружия со своей формулой урона, Elo-рейтинг и таблица лидеров. Все сообщения на русском.

## Установка

1. Скачайте `minecraft-civ-duels-<версия>.jar` со страницы [Releases](../../releases) и положите в `plugins/` сервера Paper 26.3.
2. Запустите сервер. Плагин создаст `plugins/Duels/` с настройками и лобби дуэлей `duels_lobby` (пустой мир с платформой и невидимыми стенами). Своего хаба у плагина нет: игроки приходят из хаба сервера (см. «Подключение к хабу сервера»).
3. Карта арены (необязательно). Положите папку мира с именем `duels_arena` в `world/dimensions/minecraft/` (или в корень сервера, Paper перенесёт её сам) и перезапустите. Без карты создаётся пустая тестовая платформа.
4. Зайдите на арену (`/duel admin tp arena-a`), встаньте на пол и задайте точки игроков: `/duel admin setspawn arena-a`, затем на другом месте `arena-b`.
5. При необходимости переставьте точку лобби (`setspawn lobby`), NPC (`/duel admin npc create`) и таблицу лидеров (`/duel admin board create`).
6. Настройте раздел `hub` в `config.yml` и NPC «Дуэли» в хабе сервера.

Путь игрока: хаб сервера → лобби дуэлей → арена → лобби дуэлей → хаб сервера. В лобби меню открывается правым кликом по NPC (житель-оружейник) или командой `/duel`.

## Подключение к хабу сервера

Плагину не важно, как сделан хаб и его NPC. Нужны две вещи: вход в дуэли и возврат в хаб.

**Вход.** NPC «Дуэли» в хабе должен выполнить команду:

| NPC выполняет команду | Команда |
|---|---|
| от имени игрока | `duel join` |
| от консоли | `duel join {player}` (подставьте плейсхолдер ника своего плагина NPC: Citizens `<p>`, FancyNpcs `{player_name}`, ZNPCs `%player_name%`) |

Если NPC переносит игрока на отдельный сервер (proxy-режим), команда не нужна: вошедший на сервер дуэлей сам попадает в лобби дуэлей.

**Возврат.** Кнопка «Выйти из дуэлей» в меню и `/duel exit` отправляют игрока в хаб. Во время матча выйти нельзя, очередь и тренировочная комната при выходе отменяются. Как отправлять, задаёт раздел `hub` в `config.yml`:

| Как устроен сервер | Настройка |
|---|---|
| Хаб и дуэли на одном сервере, хаб — основной мир | ничего менять не нужно: игрок телепортируется на спавн основного мира |
| Хаб на одном сервере, но в другом мире | `world: <имя мира хаба>` |
| В хаб ведёт команда (`/spawn`, `/warp hub`, `/lobby`…) | `command: "spawn"` (от консоли с ником: `command: "warp hub {player}"`; от имени игрока: `command-as-console: false`) |
| Хаб — отдельный сервер за Velocity или BungeeCord | `mode: proxy`, `server: <имя сервера хаба в прокси>`. В Velocity должен быть включён `bungee-plugin-message-channel = true` (включён по умолчанию) |

**Java API** для разработчиков хаба (необязательно): сервис `mine.deniilo.duels.api.DuelsApi` из `Bukkit.getServicesManager()`; `join(player)`, `exit(player)`, `isInDuels(player)`, `isInMatch(player)`. Подключение: JAR из Releases как `compileOnly`, `depend: [Duels]` или `softdepend` в `plugin.yml`.

```java
DuelsApi duels = Bukkit.getServicesManager().load(DuelsApi.class);
if (duels != null) {
    duels.join(player);
}
```

Инвентарь игрока при входе в лобби дуэлей не меняется. На время матча вещи сохраняются и потом возвращаются, так что предметы хаба в бой не попадают.

## Сборка

```bash
./gradlew test    # тесты
./gradlew build   # JAR в build/libs
```

Нужен JDK 25 (Gradle скачает его сам через toolchain). При пуше тега `v*` GitHub Actions собирает плагин и выпускает релиз с JAR.

## Как устроено

- **Матч.** На каждый матч создаётся копия мира арены `duels_arena_<id>`, после матча она удаляется, поэтому одновременно идёт несколько матчей (`arenas.max-concurrent`). С большой карты копируются только регионы в радиусе `arenas.copy-radius` вокруг точек. Перед матчем вещи и состояние игрока сохраняются в `plugins/Duels/restore/` и возвращаются после матча, выхода с сервера или падения сервера.
- **Бой.** Весь урон считает один движок по формуле `max(0, C·(A+P−D))`: A — атака оружия (с учётом перезарядки), P — пробитие, D — защита брони, C — крит. Ванильные Protection и Sharpness не используются. Полный комплект душ T5 делит урон больше 3,5 пополам. Щит блокирует только при реальном блоке; меч, секира и стрела отключают щит на 6 секунд, секира пробивает блок.
- **Наборы** (`kits.yml`): T3 тяжёлый, T4 тяжёлый, T4 тяжёлый (заточка), T4 кожа + лук, T4 кожа + лук (заточка), T5 душ. Предметы опознаются по PDC, прочность не тратится.
- **Рейтинг.** Elo, старт 1000, K = 32, один рейтинг на игрока для всех наборов. Хранится в SQLite `plugins/Duels/duels.db` (схема 2, старая схема переводится сама); запись матча и рейтингов — одна транзакция.
- **Тренировка.** Комнаты в меню (серая — свободна, зелёная — ждёт соперника, красная — идёт матч) и бой с ботом: бот ходит, бьёт тем же оружием, не умирает и возвращается на свою точку. Выход из тренировки не считается поражением.
- **Интерфейс.** Панель справа в лобби дуэлей (ник, рейтинг, сколько в дуэлях и в поиске), текстовый топ игроков там же.

## Настройки

| Файл | Что в нём |
|---|---|
| `config.yml` | связь с хабом сервера, миры, отсчёт и длительность матча, очередь, Elo, арены, тренировочные комнаты, таблица лидеров |
| `kits.yml` | наборы; поле `version`: при обновлении плагина с большей версией старый файл сохраняется как `kits.yml.bak` |
| `items.yml` | броня и оружие: защита, атака, пробитие, перезарядки |
| `messages.yml` | все сообщения игрокам |
| `spawns.yml` | точки lobby, arena-a, arena-b (пишет `/duel admin setspawn`) |

Кроме `kits.yml`, плагин не перезаписывает файлы настроек.

## Команды

| Команда | Что делает |
|---|---|
| `/duel` | открыть меню |
| `/duel join` | в лобби дуэлей (`/duel join <игрок>` — от консоли или с правом `duels.admin`) |
| `/duel exit` | выйти из дуэлей в хаб сервера |
| `/duel queue <набор>` | встать в рейтинговый поиск |
| `/duel leave` | выйти из очереди или сдаться (до начала боя — отмена без рейтинга) |
| `/duel stats [игрок]` | рейтинг и счёт |
| `/duel top` | таблица лидеров |

Команды администратора (право `duels.admin`):

| Команда | Что делает |
|---|---|
| `/duel admin setspawn <lobby\|arena-a\|arena-b>` | сохранить текущую позицию как точку |
| `/duel admin tp <точка>` | телепорт к точке |
| `/duel admin give <набор>`, `clear`, `info` | выдать или снять набор; показать защиту, HP и тип комплекта |
| `/duel admin npc create\|remove` | поставить NPC или убрать всех в этом мире |
| `/duel admin board create\|remove` | поставить таблицу лидеров или убрать |
| `/duel admin exitsign` | поставить табличку «[Выход]» |
| `/duel admin rating <игрок> [значение]` | показать или задать рейтинг |
| `/duel admin match solo <набор>` | матч против бота |
| `/duel admin match <игрок1> <игрок2> <набор> [ranked]` | матч двух игроков |
| `/duel admin match cancel` | отменить все матчи без рейтинга |
| `/duel admin dummy <набор>`, `dummy clear` | мишень в броне набора для проверки урона |
| `/duel admin debug on\|off` | разбор каждого удара в чате |
| `/duel admin hitme <оружие> [melee\|throw\|bow\|crossbow] [E] [P] [crit]` | имитировать удар по себе |

## Ограничения

- Absorption и Resistance не учитываются в расчёте урона.
