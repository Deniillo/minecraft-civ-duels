# minecraft-civ-duels

Автономный плагин дуэлей для Paper 26.3 (Java 25) (см. ТЗ `DUELS-STANDALONE-SPEC-RU.md`, план: проект «minecraft-civ-dev», файл `PLAN-duels-mvp.md`).

Состояние: этапы 0–1 (каркас, миры, хаб/лобби, телепорты). Бой, матчи и рейтинг — следующие этапы.

## Что нужно

- JDK 25 (IntelliJ: File → Project Structure → SDK → Add SDK → Download JDK → 25).
  Gradle сам подключит JDK 25 через toolchain, если он установлен или может быть скачан.
- Docker Desktop.
- Карта арены в `maps/arena/` (папка мира: `level.dat`, `region/`...). Уже положена.

## Сборка и запуск

```bash
./gradlew test          # unit-тесты
./gradlew build         # сборка JAR (build/libs)
./gradlew deploy        # сборка + копия JAR в docker/data/plugins

bash scripts/reset-arena.sh        # скопировать карту арены в docker/data/duels_arena
docker compose up -d
docker compose logs -f paper    # смотреть лог (выход: Ctrl+C)
docker exec duels-paper rcon-cli op <ваш_ник>   # дать себе op
docker compose down             # остановить
```

Клиент: Minecraft Java той версии, что и сервер (26.3), адрес `localhost`.
При переходе с 1.21.1 на 26.3 назад дороги нет (миры обновляются необратимо). Миры старого сервера 1.21.1 перенесены в `backups/server-1.21.1` (их можно удалить), бэкап рейтинга: `backups/duels-v2-*.db`. Папки `plugins` (рейтинг `duels.db`) и `ops.json` остаются.

В Paper 26 все миры лежат в `docker/data/world/dimensions/minecraft/<имя>` (хаб, лобби, арена и копии арен на матч). Папка `docker/data/duels_arena` из `reset-arena.sh` при старте сервера переносится туда автоматически; скрипт заодно убирает старую перенесённую копию, иначе загрузилась бы она.
Порядок первого запуска: `./gradlew deploy`, затем `bash scripts/reset-arena.sh`, затем `docker compose up -d`.

Карта арены: папка `maps/arena` (мир Minecraft не новее 26.3). Сброс карты: `docker compose down` → `bash scripts/reset-arena.sh`. После сброса карты заново задайте точки `arena-a`/`arena-b` (`/duel admin setspawn`).
Карта была сделана с модом Axiom: его правила игры (`axiom*`) из `maps/arena/level.dat` удалены, иначе Paper 26.3 пишет красную ошибку `Failed to parse saved data for ... game_rules` (оригинал: `backups/arena-level.dat.orig`).


## Хостинг для друзей (playit.gg)

Сервер работает на маке в Docker, друзья заходят через туннель playit (контейнер `duels-playit` в том же `docker-compose.yml`, проброс портов на роутере не нужен). Ключ агента: `PLAYIT_SECRET` в `.env`.

- Адрес для друзей: **`practically-honestly.tun.ply.gg`** (без порта: порт 28866 клиент найдёт по SRV-записи). Если не находит, `147.185.221.214:28866` не подойдёт (туннель не пускает по голому IP), проверьте адрес в панели playit.
- Нужно: мак не спит, Docker Desktop запущен, `docker compose up -d`. Клиент у друзей версии 26.3.
- Агент делит сеть с контейнером сервера (`network_mode: "service:paper"`), поэтому сервер для него на `127.0.0.1:25565`. Если сервер пересоздан (`docker compose up -d` после правки compose), compose пересоздаст и агент.
- Проверка, что сервер виден из интернета: `curl -s https://api.mcstatus.io/v2/status/java/practically-honestly.tun.ply.gg` → `"online":true`, версия Paper 26.3 (подтверждено 22.10.2026). С самого мака через адрес туннеля зайти нельзя (playit не пускает петлю), заходите на `localhost`. Сервис mcsrvstat проверяет по IPv6 и показывает offline — это не показатель.
- Пока `ONLINE_MODE: FALSE`: любой, кто знает адрес, может зайти под чужим ником (в том числе вашим, с правами op). Белый список или проверка лицензии отложены; не раздавайте адрес широко.

## Быстрая проверка одной командой

```bash
bash scripts/dev-check.sh
```

Скрипт при необходимости установит Docker Desktop на Mac (`scripts/install-docker-mac.sh`, спросит пароль администратора), запустит тесты, соберёт плагин, поднимет сервер и проверит лог. В конце: OK/FAIL по каждому пункту.

## Команды

| Команда | Что делает |
|---|---|
| `/duel` | открыть меню (то же, что правый клик по NPC в хабе и лобби) |
| `/duel lobby` | в лобби дуэлей |
| `/duel queue <набор>` | встать в рейтинговый поиск (поиск только рейтинговый) |
| `/duel admin exitsign` | поставить табличку «[Выход]» там, где вы стоите (на готовой карте арены) |
| `/duel stats [игрок]` | общий рейтинг и счёт |
| `/duel top` | таблица лидеров по общему рейтингу |
| `/duel hub` | в хаб |
| `/duel admin setspawn <hub\|lobby\|arena-a\|arena-b>` | сохранить текущую позицию как точку (право `duels.admin`) |
| `/duel admin tp <ключ>` | телепорт к точке |
| `/duel admin give <набор>` | выдать набор (t3_heavy, t4_heavy, t5_soul, t4_heavy_max) |
| `/duel admin clear` | снять набор и эффекты |
| `/duel leave` | выйти из очереди или сдаться в матче (до начала боя — отмена без рейтинга) |
| `/duel admin npc create\|remove` | поставить NPC на свою позицию или убрать всех NPC в этом мире |
| `/duel admin rating <игрок> [значение]` | показать или задать общий рейтинг (для проверок) |
| `/duel admin board create\|remove` | поставить текстовую таблицу лидеров на свою позицию или убрать все в этом мире |
| `/duel admin match solo <набор>` | матч против мишени-соперника: проверка всего цикла в одиночку |
| `/duel admin match <игрок1> <игрок2> <набор> [ranked]` | матч двух игроков |
| `/duel admin match cancel` | отменить все матчи (без рейтинга) |
| `/duel admin info` | показать защиту, HP, скорость и тип комплекта по надетой броне |
| `/duel admin dummy <набор>` | создать мишень в броне набора и включить для себя боевой режим (только на арене: в хабе и лобби мирный режим) |
| `/duel admin dummy clear` | убрать все мишени и выключить боевой режим |
| `/duel admin debug on\|off` | показывать в чате разбор каждого удара (A, P, D, C, итог) |
| `/duel admin hitme <оружие> [melee\|throw\|bow\|crossbow] [E] [P] [crit]` | имитировать удар по себе против надетой брони |

Точки лежат в `plugins/Duels/spawns.yml`. Для арены встаньте на нужное место и выполните `setspawn arena-a`, затем второе место: `setspawn arena-b` (на карте с несколькими площадками выберите одну).

## Ручная проверка этапа 4: матч (в одиночку)

Подготовка: в `/duel admin setspawn arena-a` и `arena-b` задайте две точки на арене (для пустой платформы: `/duel admin tp arena-a`, отойдите на 8 блоков, `setspawn arena-a`; затем в другую сторону `setspawn arena-b`). Положите в инвентарь пару предметов (например, блоки) и запомните здоровье, чтобы проверить возврат.

| Что сделать | Ожидаемый исход |
|---|---|
| `/duel admin match solo t4_heavy` | Вы на точке arena-a, на arena-b стоит мишень-соперник в броне, у вас набор t4_heavy |
| Попробовать двигаться первые 5 секунд | Движение по земле заблокировано, видны цифры 5…1 |
| Ударить мишень в отсчёт | Урона нет (до ACTIVE урон запрещён) |
| «БОЙ!»: бить мишень, пока не умрёт | Итог «Победа», причина «гибель», «Тренировка, рейтинг не изменён» |
| Через 3 секунды после итога | Вы в прежнем месте, прежние предметы и здоровье возвращены, набор исчез, сообщение «вещи и состояние возвращены» |
| `/duel admin match solo t4_heavy`, во время боя `/duel leave` | Поражение, причина «выход или сдача», возврат вещей |
| Запуск матча и `/duel leave` в отсчёт | Матч отменён без рейтинга, вещи возвращены |
| Запуск матча, ждать 10 минут (для проверки поставьте `max-duration-seconds: 20` и перезапустите) | Ничья, причина «вышло время» |
| В бою погибнуть самому (упасть в пустоту арены или `/kill` от админа) | Поражение по гибели; возрождение сразу, без экрана смерти, возврат вещей |
| Запуск матча и закрытие клиента во время боя, повторный вход | Вещи и состояние возвращены, вы не в наборе матча |
| Запуск матча и `docker compose restart paper` | Матч отменён без рейтинга, после входа вещи возвращены |
| Во время матча `/gamemode`, `/home` (не админом) или любая не-`/duel` команда | Блокируется сообщением |
| Во время матча снять броню в инвентаре, выбросить оружие | Нельзя |
| `/duel admin match solo t4_heavy` дважды подряд | Второй запуск: «Игрок уже участвует в матче» |
| `/duel admin match cancel` во время боя | Отмена «отмена администратором», возврат вещей |
| Два игрока: `/duel admin match A B t4_heavy` | Оба на своих точках, одинаковые наборы, бой, итог, возврат |
| Два игрока: оба умирают одновременно (например, оба падают) | Ничья, «оба проиграли одновременно» |

## Ручная проверка этапа 5–6: NPC, меню, очередь, рейтинг (в одиночку)

Подготовка: пересоберите и перезапустите сервер (`bash scripts/dev-check.sh`). Точки arena-a и arena-b должны быть заданы в мире арены.

| Действие | Ожидаемый результат |
|---|---|
| Зайти на сервер | Вы в хабе, в трёх блоках перед вами стоит житель-оружейник с именем «Дуэли (ПКМ)», неподвижный |
| Ударить жителя | Урона нет, житель стоит |

### База данных

Файл `docker/data/plugins/Duels/duels.db` (SQLite, схема версии 2, версия хранится в `PRAGMA user_version`; база версии 1 переводится автоматически при запуске, см. `RatingRepositoryTest.migratesSchemaOneWithPerKitRatingsIntoOneRating`). Таблицы: `players`, `ratings` (один рейтинг на игрока), `matches` (журнал со значением `match_id` без повторов, рейтинг до и после). Запись матча и обновление рейтингов идут одной транзакцией; повторная запись того же `match_id` ничего не меняет. Копия для бэкапа: остановить сервер и скопировать `duels.db`, либо `sqlite3 duels.db ".backup copy.db"`. Запись выполняется в главном потоке (несколько миллисекунд на SQLite), поэтому следующий матч игрока всегда видит уже сохранённый рейтинг.

| Действие | Ожидаемый результат |
|---|---|
| Запуск 26.3 на базе со старого сервера | `PRAGMA user_version` = 2, данные на месте (подтверждено 22.10.2026: 3 игрока, 32 матча, 3 рейтинга; база была переведена на v2 ещё на 1.21.1; бэкап `backups/duels-v2-*.db`) |

## Ручная проверка: арены, защита, наборы

Карта `maps/arena` — kit-PvP карта «DKP» (204 МБ): хаб у (0,0) и четыре закрытые площадки 96×96 далеко друг от друга (z ≈ 9920 пустыня, 14912 снег, 19920 лес, 24912 лес). Дуэли идут на **пустынной площадке**: пол из красного песка (y 2–5), стены из бедрока, сверху потолок из барьеров, снаружи пустота. Точки: `arena-a` = (−53.5, 6, 9940.5) лицом на восток, `arena-b` = (−23.5, 3, 9940.5) лицом на запад, 30 блоков друг от друга (старые точки платформы лежат в `backups/spawns-old-platform.yml`). Арены: для каждого матча плагин копирует мир `duels_arena` в отдельный мир `duels_arena_<id>` и удаляет его после матча. Исходный `duels_arena` служит шаблоном: точки `arena-a` и `arena-b` задаются в нём. Сколько матчей идёт одновременно, задаёт `arenas.max-concurrent` в `config.yml` (по умолчанию 4). Копия большой карты занимает место и время при старте матча, подберите размер карты под это.

## Приёмка MVP

Автоматически (`bash scripts/dev-check.sh`, раздел тестов): формулы урона и брони, наборы и запреты, состояние матча (победа, ничья, отмена), арена, очередь, Elo (рейтинг общий для всех наборов; 1000 против 1000: ±16; 1200 побеждает 1000: ±8; 1000 побеждает 1200: ±24), SQLite (идемпотентность, откат, повторное открытие).

Вручную: таблицы этапов 0–5 выше. Одному игроку недоступны: рейтинговая очередь двух людей и расширение окна подбора; эти строки помечены «С двумя игроками».

Не входит в MVP: адаптер Velocity/BungeeCord (интерфейс `HubAdapter` готов, есть локальная реализация), Absorption и Resistance в расчёте урона, карта арены (пустая платформа, если `maps/arena` нет).
