## 1. Что это и как игрок проходит через дуэли

Duels — плагин для Paper 26.3 (Java 25): рейтинговые бои 1 на 1, тренировочные комнаты, бой с ботом-мишенью, свои наборы брони и оружия, свой расчёт урона, Elo-рейтинг. Своего хаба у плагина нет: он встраивается в хаб сервера.

```
 Хаб сервера (их код)                       Плагин Duels
┌──────────────────────┐   duel join   ┌────────────────────────┐   поиск/комната/бот   ┌───────────────────────┐
│ NPC «Дуэли»          │──────────────▶│ лобби дуэлей           │──────────────────────▶│ копия арены на матч   │
│ NPC других мини-игр  │               │ duels_lobby            │◀──────────────────────│ duels_arena_<id>      │
└──────────────────────┘◀──────────────│ наш NPC-меню, топ,     │   итог матча,          └───────────────────────┘
          ▲            duel exit /     │ панель справа          │   вещи возвращены
          │            кнопка меню     └────────────────────────┘
```

- **Вход.** NPC «Дуэли» в хабе выполняет `duel join`. Игрок попадает на платформу лобби дуэлей.
- **Лобби дуэлей.** Здесь наш NPC (житель-оружейник) открывает меню: рейтинговый поиск по набору, тренировочные комнаты, бой с ботом, статистика, топ. Рядом висит текстовый топ игроков, справа панель с рейтингом. В лобби нет урона и голода, блоки не ломаются, упавший в пустоту возвращается на платформу.
- **Матч.** Под каждый матч создаётся своя копия карты арены. Перед матчем вещи игрока сохраняются на диск, он получает набор. После матча набор снимается, вещи и здоровье возвращаются, игрок снова в лобби дуэлей.
- **Выход.** Кнопка «Выйти из дуэлей» в меню или `/duel exit` отправляет игрока в хаб сервера. Во время матча выход запрещён. Очередь и тренировочная комната при выходе отменяются.

## 2. Подключение к хабу: выбор способа

Код хаба нам недоступен, поэтому плагин поддерживает оба распространённых варианта. Режим переключается в `plugins/Duels/config.yml`, раздел `hub`:

```yaml
hub:
  mode: local                 # local — хаб на этом сервере; proxy — хаб на другом сервере за прокси
  command: ""                 # local: команда возврата в хаб, без «/»; {player} — ник
  command-as-console: true    # local: от консоли (true) или от имени игрока (false)
  world: ""                   # local, если command пуст: мир хаба; пусто — основной мир сервера
  server: lobby               # proxy: имя сервера хаба в настройках прокси
```

Как понять, какой у них вариант:

| Признак | Способ |
|---|---|
| В `/plugins` их сервера видны и плагин хаба, и плагины мини-игр; мини-игры — разные миры (`/mv list`, `/worlds`) | **A**, тот же сервер |
| В табе или чате видно переключение сервера, в настройках есть Velocity/BungeeCord/Waterfall, у каждой мини-игры свой сервер | **B**, прокси |
| Игроку при переходе в мини-игру меняют инвентарь, а `/plugins` одинаковый | скорее **A** с плагином инвентарей по мирам (см. [раздел 10](#10-частые-проблемы)) |

Пока способ не выбран, ничего удалять не нужно: по умолчанию работает способ A с возвратом на спавн основного мира.

## 3. Способ A: хаб на том же сервере

Их хаб и наши миры (`duels_lobby`, `duels_arena`, `duels_arena_<id>`) живут в одном Paper.

**Шаг 1. Установка.** JAR в `plugins/`, карта арены в `world/dimensions/minecraft/duels_arena` (или папкой `duels_arena` в корне сервера, Paper перенесёт её сам), перезапуск. Затем `/duel admin setspawn arena-a` и `arena-b` на полу арены.

**Шаг 2. Вход: NPC «Дуэли» в хабе.** В их плагине NPC добавить действие-команду:

| Плагин NPC | Как добавить | Команда |
|---|---|---|
| Citizens (+ Denizen/CommandNPC) | `/npc command add -p duel join` (от игрока) или `/npc command add duel join <p>` (от консоли) | `duel join` / `duel join <p>` |
| FancyNpcs | `/npc action <имя> RIGHT_CLICK add player_command duel join` | `duel join` |
| ZNPCsPlus | действие `PLAYER_CMD` (от игрока) или `CONSOLE_CMD` (от консоли) | `duel join` или `duel join %player_name%` |
| Свой код | `player.performCommand("duel join")` или [API](#5-java-api-для-разработчиков-хаба) | — |

Синтаксис команд плагинов NPC меняется от версии к версии: сверьте с документацией их плагина. `duel join` от игрока прав не требует. `duel join <ник>` требует `duels.admin`; у консоли это право есть всегда.

**Шаг 3. Выход: как вернуть игрока в хаб.** Выбрать одну строку:

| Как в их хабе | Настройка `hub` |
|---|---|
| Хаб — основной мир сервера (`world` из `server.properties`) | ничего не менять |
| Хаб — отдельный мир, например `hub` | `world: hub` |
| В хаб ведёт команда `/spawn`, `/hub`, `/lobby` | `command: "spawn"`, `command-as-console: false` (команда от игрока) |
| В хаб ведёт команда с ником (`/warp hub <ник>`, `/tp <ник> …`) | `command: "warp hub {player}"` (от консоли) |

Совет: если у хаба есть своя команда возврата, лучше указать её, а не мир. Тогда хаб сам выдаст игроку свои предметы и режим игры.

**Шаг 4.** Перезапуск сервера. В логе должна быть строка `Duels enabled, хаб: этот сервер`.

## 4. Способ B: отдельный сервер за Velocity или BungeeCord

Дуэли стоят на своём Paper-сервере за прокси, хаб — на другом.

**Шаг 1. Сервер дуэлей.** Отдельный Paper 26.3 с нашим JAR и картой арены (как в способе A, шаг 1).

**Шаг 2. Прокси.** Добавить сервер дуэлей в список серверов прокси (`velocity.toml` → `[servers]`, у BungeeCord — `config.yml` → `servers`), например под именем `duels`. Для Velocity на сервере дуэлей включить пересылку игроков: `config/paper-global.yml` → `proxies.velocity.enabled: true`, тот же `secret`, что в прокси, `online-mode=false` в `server.properties` (проверку лицензии делает прокси).

**Шаг 3. Вход.** NPC «Дуэли» в хабе переводит игрока на сервер `duels` средствами их хаба (обычно действие «connect»/«server» у плагина NPC или `/server duels`). Команда `duel join` не нужна: при входе на сервер дуэлей игрок сам попадает в лобби дуэлей.

**Шаг 4. Выход.** В `config.yml` сервера дуэлей:

```yaml
hub:
  mode: proxy
  server: lobby     # имя сервера хаба в прокси
```

Плагин отправляет игрока через канал `BungeeCord` (сообщение `Connect`). Velocity понимает этот канал, если в `velocity.toml` `bungee-plugin-message-channel = true` (так по умолчанию).

**Шаг 5.** Перезапуск. В логе: `Duels enabled, хаб: сервер lobby через прокси`.

Рейтинг хранится в SQLite на сервере дуэлей. Пока сервер дуэлей один, этого хватает. Для нескольких серверов дуэлей понадобится общая база (см. [раздел 9](#9-данные-база-и-файлы)).

## 5. Java API для разработчиков хаба

Не обязательно: команды из разделов 3 и 4 покрывают всё. API нужен, если хаб написан своим кодом и удобнее вызвать метод.

```java
import mine.deniilo.duels.api.DuelsApi;

DuelsApi duels = Bukkit.getServicesManager().load(DuelsApi.class);
if (duels != null) {
    duels.join(player);
}
```

| Метод | Что делает |
|---|---|
| `boolean join(Player)` | отправить в лобби дуэлей; `false`, если игрок в матче или лобби недоступно |
| `boolean exit(Player)` | отменить очередь и комнату, отправить в хаб по настройке `hub`; `false` во время матча |
| `boolean isInDuels(Player)` | игрок в мире дуэлей (лобби или арена) |
| `boolean isInMatch(Player)` | игрок участвует в матче |

Подключение: JAR из [Releases](https://github.com/Deniillo/minecraft-civ-duels/releases) как `compileOnly`, в `plugin.yml` хаба `softdepend: [Duels]`. Все методы вызываются из главного потока сервера.

## 6. Что убрать, когда способ выбран

Сейчас плагин поддерживает оба способа и старые команды. Когда способ известен, лишнее можно удалить, чтобы не путать администраторов и не держать мёртвый код. Перед удалением кода убедитесь, что способ проверен на живом сервере ([раздел 7](#7-проверка-после-подключения)).

### Выбран способ A (тот же сервер)

| Что | Где | Действие |
|---|---|---|
| Прокси-адаптер | `hub/ProxyHubAdapter.java` | удалить |
| Выбор режима | `DuelsPlugin`: тернарник `hubSettings.mode() == PROXY ? new ProxyHubAdapter… : new LocalHubAdapter…` и строка лога с режимом | оставить только `new LocalHubAdapter(hubSettings)` |
| Вход в лобби при входе на сервер | `LobbyListener`: поле `joinToLobby` и ветка в `onJoin` | удалить (в способе A игрок входит в хаб, а не к нам) |
| Поля режима | `HubSettings`: `Mode`, `server`, проверка `hub.server` | удалить |
| Ключи настроек | `config.yml`: `hub.mode`, `hub.server` | удалить |
| Тесты | `HubSettingsTest`: `proxyNeedsServerName`, `unknownModeIsRejected`, `proxyConnectMessageIsBungeeFormat` | удалить |
| Документация | README и этот файл: разделы про proxy | удалить |

Если возврат идёт командой (`hub.command`), из `LocalHubAdapter` можно убрать ветку с миром и ключ `hub.world`, и наоборот.

### Выбран способ B (прокси)

| Что | Где | Действие |
|---|---|---|
| Локальный адаптер | `hub/LocalHubAdapter.java` | удалить |
| Выбор режима | `DuelsPlugin` | оставить `new ProxyHubAdapter(this, hubSettings.server())`, вход в лобби при входе на сервер — всегда |
| Поля локального режима | `HubSettings`: `Mode`, `command`, `commandAsConsole`, `world`, `commandFor` | удалить, оставить `server` |
| Ключи настроек | `config.yml`: `hub.mode`, `hub.command`, `hub.command-as-console`, `hub.world` | удалить |
| Вход с ником | `DuelCommand.join`: форма `/duel join <ник>` | можно удалить (на отдельный сервер игрок приходит сам) |
| Тесты | `HubSettingsTest`: `withoutSectionHubIsMainWorldOfThisServer`, `localCommandTakesPlayerName` | удалить или переписать |

### В любом случае

| Что | Где | Почему |
|---|---|---|
| Старые названия команд `/duel lobby` и `/duel hub` | `DuelCommand.onCommand`: `case "join", "lobby"` и `case "exit", "hub"` | оставлены для совместимости, после перехода на `join`/`exit` не нужны |
| Java API, если хаб им не пользуется | `api/DuelsApi.java`, регистрация в `DuelsPlugin` (`getServicesManager().register`) | `DuelsGateway` тогда может не реализовывать интерфейс |

## 7. Проверка после подключения

| Действие | Ожидаемый результат |
|---|---|
| Старт сервера | В логе `Duels enabled, хаб: …` с нужным режимом, нет строк `ERROR` от Duels |
| Клик по NPC «Дуэли» в хабе | Игрок на платформе лобби дуэлей, сообщение «Вы в лобби дуэлей», режим приключения (у кого нет `duels.admin`) |
| Правый клик по нашему жителю в лобби | Открывается меню дуэлей |
| Меню → «Выйти из дуэлей» | Игрок в хабе сервера, сообщение «Возвращаем в лобби сервера…» |
| Встать в поиск и нажать «Выйти из дуэлей» | Поиск отменён, игрок в хабе |
| Во время матча `/duel exit` | «Сначала завершите матч: /duel leave», игрок остаётся в бою |
| Во время матча любая команда хаба (`/spawn`, `/hub`) | Блокируется: в матче доступны только `/duel` |
| Тренировка с ботом, затем выход в хаб | Вещи хаба на месте, набора дуэлей нет |
| Выйти с сервера посреди матча и зайти снова | Вещи и здоровье возвращены |
| Способ B: зайти на сервер дуэлей через прокси | Сразу в лобби дуэлей |
| Способ B: «Выйти из дуэлей» | Переход на сервер хаба |
| `hub.command` указывает на несуществующую команду | «Лобби сервера недоступно. Сообщите администратору.» |
| Консоль: `duel join Nobody` | «Игрок Nobody не в сети.» |

## 8. Архитектура

### Общая схема

```
DuelsPlugin (onEnable: читает настройки, создаёт сервисы, регистрирует слушатели и команду)
│
├── hub/        DuelsGateway (вход/выход, реализует api/DuelsApi)
│               HubAdapter ─┬─ LocalHubAdapter (команда или мир на этом сервере)
│                           └─ ProxyHubAdapter (канал BungeeCord → Connect)
├── world/      WorldService (миры лобби и арены), ArenaInstanceService (копия арены на матч),
│               SpawnStore (spawns.yml), ProtectionListener (блоки), ExitSignService (табличка «[Выход]»)
├── match/      MatchManager → DuelMatch (фазы, итог), MatchListener (смерть, выход, команды),
│               RestoreStore (вещи до матча), ArenaPool
├── combat/     DuelCombatEngine (весь урон в матче), DamageCalculator (формулы), DummyService (бот)
├── profile/    ItemCatalog (items.yml), KitCatalog (kits.yml), ArmorSetCalculator, правила оружия
├── item/, kit/ ItemFactory/ItemReader (предметы с метками PDC), KitService (выдача набора)
├── queue/      QueueService (подбор по рейтингу), QueueCoordinator (запуск матчей)
├── training/   TrainingRooms (комнаты), TrainingCoordinator
├── rating/     RatingRepository (SQLite), EloCalculator, RatingService (итог → база), StatsCommands
├── menu/       DuelMenu (GUI)       npc/      NpcService, NpcListener (житель-меню)
├── board/      LeaderboardService   scoreboard/ SidebarService (панель справа)
├── listener/   LobbyListener (лобби: урон, голод, пустота, вход на сервер)
├── command/    DuelCommand (/duel)  message/ Messages (messages.yml, MiniMessage)
└── config/     DuelsSettings (миры), SpawnPoint
```

Все связи передаются через конструкторы в `DuelsPlugin.onEnable`, без статических синглтонов. Наружу открыт только `api/DuelsApi`.

### Жизненный цикл матча

1. **Подбор.** `QueueCoordinator` раз в секунду просит `QueueService` найти пару: тот же набор, рейтинги в пределах окна. Окно растёт с ожиданием (`queue.*` в `config.yml`). Тренировочная комната или бот запускают матч сразу.
2. **Арена.** `ArenaInstanceService` копирует мир-шаблон `duels_arena` в `duels_arena_<id8>`. Копируются только регионы в радиусе `arenas.copy-radius` вокруг точек, без `session.lock`, `playerdata`, `chunk_tickets.dat` и `data/paper/metadata.dat`. Точки `arena-a`/`arena-b` опускаются на пол. Одновременно идёт не больше `arenas.max-concurrent` матчей.
3. **Сохранение игрока.** `RestoreStore` пишет `plugins/Duels/restore/<uuid>.yml` (инвентарь, броня, здоровье, еда, опыт, эффекты, режим, место) **до** любого изменения игрока. Если записать не удалось, матч не начинается.
4. **Набор.** `KitService` очищает инвентарь и выдаёт набор: предметы помечены PDC (`item_id`, уровни заточки, `session_id`) и неразрушимы.
5. **Отсчёт.** В обычном матче 3 секунды, урона нет. С ботом отсчёта нет.
6. **Бой.** `DuelCombatEngine` (обработчики `HIGHEST`) заменяет ванильный урон между участниками на `max(0, C·(A+P−D))`. Щит, кулдауны, запрет броска трезубца в HEAVY, SOUL T5 — там же. Команды, кроме `/duel`, заблокированы.
7. **Итог.** Смерть, сдача (`/duel leave`), выход с сервера, время (`match.max-duration-seconds`) или отмена администратором. Итог собирается в конце тика, поэтому две смерти в одном тике дают ничью. Выход из тренировки не называется поражением.
8. **Запись.** `RatingService` пишет матч и рейтинги в SQLite одной транзакцией (только матчи людей, не с ботом). Рейтинг меняется только в рейтинговом матче.
9. **Возврат.** Через `match.result-delay-ticks` игроки получают вещи из `restore/` с полным здоровьем, попадают в лобби дуэлей. Копия арены выгружается и удаляется с диска.

После падения сервера: при старте удаляются оставшиеся копии арен, при входе игрока `MatchListener` возвращает его вещи из `restore/`.

### Правила, которые держит код

- Урон в матче считает только `DuelCombatEngine`. Ванильные Protection и Sharpness не используются, второй слой защиты не добавлять.
- Предметы опознаются по PDC, не по названию: переименование на наковальне ничего не меняет.
- Всё, что трогает Bukkit, и запись в SQLite выполняются в главном потоке. Запись матча занимает миллисекунды, зато следующий матч всегда видит уже сохранённый рейтинг.
- Сообщения игрокам только через `Messages` (`messages.yml`), на русском.

### Миры

Paper 26 хранит миры в `world/dimensions/minecraft/<имя>`; `World#getWorldFolder()` указывает туда. Плагин создаёт:

| Мир | Откуда | Что в нём |
|---|---|---|
| `duels_lobby` | генерируется пустым, если нет (`worlds.lobby.generate-if-missing`) | платформа 25×25 и стены из барьеров; NPC, топ |
| `duels_arena` | готовая карта; если её нет — пустая платформа с барьерами | шаблон, в нём задаются точки `arena-a`/`arena-b` |
| `duels_arena_<id8>` | копия шаблона на один матч | удаляется после матча |

Имена миров задаются в `worlds.*` в `config.yml`.

## 9. Данные: база и файлы

### Файлы в `plugins/Duels/`

| Файл | Кто пишет | Что в нём |
|---|---|---|
| `config.yml` | администратор | хаб, миры, матч, очередь, Elo, арены, комнаты, топ |
| `kits.yml` | администратор; плагин обновляет при новой `version` в JAR (старый → `kits.yml.bak`) | наборы |
| `messages.yml` | администратор | тексты (MiniMessage) |

| `duels.db` | плагин | рейтинг и журнал матчей (SQLite) |
| `restore/<uuid>.yml` | плагин | вещи игрока на время матча; удаляется после возврата |
| `combat-debug.log` | плагин, если `debug.combat-file-log: true` | разбор каждого удара |

Справочник предметов `items.yml` лежит внутри JAR и с диска не читается.

### База `duels.db` (SQLite)

Драйвер `sqlite-jdbc` встроен в Paper, отдельно ставить не нужно. Версия схемы хранится в `PRAGMA user_version` (сейчас 2), миграции выполняются при старте в `RatingRepository`.

```sql
CREATE TABLE players (
  uuid TEXT PRIMARY KEY,
  name TEXT NOT NULL                -- последний известный ник
);

CREATE TABLE ratings (               -- один рейтинг на игрока для всех наборов
  uuid   TEXT PRIMARY KEY,
  rating INTEGER NOT NULL,           -- старт 1000
  wins   INTEGER NOT NULL DEFAULT 0,
  losses INTEGER NOT NULL DEFAULT 0,
  draws  INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_ratings_rating ON ratings (rating DESC);

CREATE TABLE matches (               -- журнал матчей людей (с ботом не пишется)
  match_id TEXT PRIMARY KEY,         -- повторная запись того же матча ничего не меняет
  kit_id TEXT NOT NULL, ranked INTEGER NOT NULL,
  player_a TEXT NOT NULL, player_b TEXT NOT NULL,
  outcome TEXT NOT NULL,             -- WIN / DRAW / CANCELLED
  winner TEXT, loser TEXT,
  reason TEXT NOT NULL,              -- DEATH, FORFEIT (сдача/выход), TIMEOUT, SIMULTANEOUS, LEFT_BEFORE_START, ADMIN, SHUTDOWN, ERROR
  duration_ms INTEGER NOT NULL, finished_at INTEGER NOT NULL,
  rules_version INTEGER NOT NULL,
  a_before INTEGER, a_after INTEGER, b_before INTEGER, b_after INTEGER  -- рейтинг до и после
);
```

- Матч и обновление рейтингов — одна транзакция: либо записано всё, либо ничего.
- Elo: старт 1000, K = 32, нижняя граница `elo.floor`. 1000 против 1000: ±16.
- Бэкап: остановить сервер и скопировать `duels.db`, либо на ходу `sqlite3 duels.db ".backup copy.db"`.
- Несколько серверов дуэлей с общим рейтингом SQLite не потянет. Тогда `RatingRepository` нужно перевести на MySQL/PostgreSQL. SQL там стандартный, кроме `INSERT OR IGNORE` и `ON CONFLICT … DO UPDATE` — у MySQL это `INSERT IGNORE` и `ON DUPLICATE KEY UPDATE`.

## 10. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Клик по NPC «Дуэли» ничего не делает | NPC выполняет команду от консоли без ника: нужно `duel join <плейсхолдер ника>` |
| «Мир недоступен: lobby» | мир `duels_lobby` не загрузился: см. ошибки в логе при старте, `worlds.lobby.generate-if-missing` |
| «Лобби сервера недоступно» | `hub.command` не выполнилась (нет такой команды или прав у игрока при `command-as-console: false`) или мира `hub.world` нет |
| Способ B: кнопка выхода ничего не делает | у Velocity выключен `bungee-plugin-message-channel`, или `hub.server` не совпадает с именем в прокси |
| После перехода в дуэли у игрока чужой инвентарь | на сервере плагин инвентарей по мирам (например, Multiverse-Inventories). Миры `duels_lobby`, `duels_arena` и все `duels_arena_*` положите в одну группу, иначе плагин инвентарей и наш `RestoreStore` будут менять вещи друг другу |
| Игрок в лобби дуэлей не может ломать блоки и получать урон | так задумано; у `duels.admin` творческий режим и права остаются |
| Таблица топа или NPC задвоились | плагин удаляет дубликаты сам при обновлении топа (раз в `leaderboard.update-seconds`) и при старте; убрать вручную: `/duel admin board remove`, `/duel admin npc remove` |
| Матч не стартует: «под точкой arena-a нет пола» | точка над пустотой: встать на пол арены и `/duel admin setspawn arena-a` |
