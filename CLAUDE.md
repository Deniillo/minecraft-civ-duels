# minecraft-civ-duels — памятка для Claude Code

Автономный плагин дуэлей для **Paper 26.3, Java 25** (Gradle Kotlin DSL). Пакет `mine.deniilo.duels`, исходники в `src/main/java/mine/deniilo/duels`.
ТЗ: `DUELS-STANDALONE-SPEC-RU.md` (лежит в `~/Downloads`; при работе над боем и предметами сверяйся с ним, числа и формулы оттуда).
Пользователь John пишет по-русски, отвечай по-русски. Тестирует один (второго игрока часто нет).

## Правила работы
- После каждой правки: `./gradlew build` (тесты и сборка). На каждую фичу — автотест.
- `README.md` — описание для пользователей плагина (установка, устройство, настройки, команды); без ручных чек-листов и локального сервера.
- Коммиты без строк `Co-Authored-By`/упоминаний Claude. Релиз: поднять `version` в `build.gradle.kts`, запушить тег `v<версия>` — GitHub Actions выпустит релиз с JAR.
- Никакой зависимости от CivCraft. Предметы опознаются по PDC, не по названию.
- Весь урон считает один движок `combat/DuelCombatEngine` (приоритет HIGHEST), формулы в `DamageCalculator` (ТЗ раздел 7). Не добавляй второй слой защиты (ванильные Protection/Sharpness не используются).
- Комментарии в коде почти не пишем: только в самых неочевидных местах (ловушки API Paper, порядок операций, без которого ломаются данные). Никаких javadoc-пересказов, разделителей «// ----», истории правок.
- Сообщения игроку только русские, через `Messages` (`messages.yml`). Не оставляй английских строк в игре.
- Операции Bukkit — только в главном потоке. SQLite пишется синхронно в главном потоке, одна транзакция на матч.
- Файлы настроек в папке сервера не перезаписываются сами. Исключение: `kits.yml` с полем `version` (при повышении версии в jar старый сохраняется как `.bak`). Меняешь `kits.yml` — повышай `version`.

## Как устроено
- Поток игрока: хаб → лобби → арена. Меню открывается правым кликом по NPC (житель-оружейник) и командой `/duel`.
- `match/`: `DuelMatch`, `MatchManager`, `MatchState`; `RestoreStore` пишет `plugins/Duels/restore/<uuid>.yml` до изменений игрока и возвращает его с полным HP.
- `world/ArenaInstanceService`: на каждый матч копия шаблонного мира `duels_arena` в `duels_arena_<id8>`, после матча удаляется. Хаб и лобби — генерируемые пустые миры с барьерами по краям.
- `queue/` (рейтинговый поиск, окно рейтинга расширяется), `rating/` (Elo: старт 1000, K=32; SQLite `duels.db`, схема v2, **один рейтинг на игрока для всех наборов**), `training/` (комнаты: серый/зелёный/красный краситель; бот-мишень ходит, бьёт тем же мечом, не умирает, воскресает на своей точке), `scoreboard/` (сайдбар справа), `board/` (текстовый топ в лобби, в хабе не ставится), `menu/` (GUI), `npc/`.
- Бой: щит работает только при реальном блоке; меч/секира/стрела отключают щит на 120 тиков; секира пробивает блок; трезубец: ближний бой в любой броне, бросок запрещён в полном HEAVY (кулдаун 120 тиков, Loyalty III).
- Наборы (`kits.yml`): T3 тяжёлый, T4 тяжёлый, T5 душ, T4 тяжёлый (заточка), T4 кожа + лук, T4 кожа + лук (заточка). Меню не показывает состав и рейтинг наборов, только название.
- Тренировка с ботом: без отсчёта. Обычный матч: отсчёт 3 секунды.

## Известные особенности и риски
- Проект собирается без предупреждений на `paper-api 26.3.build.211-stable` (22.10.2026). Правила мира — через `org.bukkit.GameRules`. Тест движка боя без сервера: Mockito + сервер-мок через reflection (`DuelCombatEngineTest`).
- Копия на матч берёт только регионы в `arenas.copy-radius` вокруг точек; висящие точки опускаются на пол (`ArenaInstanceService.onGround`); бот, упавший в пустоту, возвращается без зачёта.
- В Paper 26 миры лежат в `world/dimensions/minecraft/<имя>`; `World#getWorldFolder()` указывает туда. Копии арены кладутся рядом с шаблоном, без `data/paper/metadata.dat` (иначе «duplicate world»).
- Не поддерживаются Absorption и Resistance в расчёте урона.
- Пока нет прокси Velocity/BungeeCord: хаб и дуэли на одном сервере (`HubAdapter` — локальная реализация).
